# Часть для проверки Юлей: понятные ошибки импорта
Это подготовленная доработка существующего проекта, а не подтверждение личного авторства.

## Что изменилось
LegacyBankCsv.Row теперь хранит физический номер строки lineNumber. Считаем заголовок первой строкой, пустые строки тоже считаются. LegacyBankAdapter использует этот номер в ошибках преобразования даты, суммы и категории. Ошибки кавычек перехватываются в LegacyBankCsv и получают тот же префикс CSV line N.

## Проверка
На Windows с JDK 17+ выполнить test.bat, затем java -cp out moneypilot.CsvLineErrorTest.
Для новой версии приложения выполнить build.bat и run.bat. JAR из main до сборки не включает доработку.

## Демонстрация
Создать CSV с заголовком date;amount;category;note и двумя строками:
2026-11-01;-100;Food;Lunch
2026-99-01;-200;Food;Bad date
Импорт выдаст CSV line 3 с описанием ошибки даты. Никакие операции из файла не добавятся. Исправь дату и повтори импорт.

## Что объяснить
Parser читает поля и сохраняет номер строки. Adapter преобразует чужую модель Row в нашу Transaction и добавляет контекст ошибки. Builder продолжает проверять итоговый объект. Номер нельзя считать индексом в списке плюс 2, потому что parser пропускает пустые строки.

Перед отправкой прочитай diff и запусти проверки. После авторизации своим аккаунтом можно доработать эту ветку и отправить собственный коммит. Пароль и токен никому пересылать не нужно.
