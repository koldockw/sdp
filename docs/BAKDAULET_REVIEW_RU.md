# Часть для проверки Бакдаулетом: ограничение Undo
Это подготовленная доработка существующего проекта, а не подтверждение личного авторства.

## Что изменилось
CommandHistory хранит не больше 100 последних действий. Можно передать другой положительный лимит в конструктор. При переполнении removeLast удаляет самую старую запись. push и pop работают с новейшей записью в начале Deque. Операции и сохранённые траты не удаляются, удаляется только возможность отменить старое действие.

## Зачем
Каждая запись истории содержит копию списка операций. Ограничение не даёт количеству снимков расти бесконечно в долгом сеансе. Это ограничение количества снимков, а не фиксированный предел памяти: один снимок всё ещё занимает O(n) ссылок.

## Проверка на Windows с JDK 17+
Сначала test.bat, затем java -cp out moneypilot.HistoryLimitTest.
Для новой версии приложения выполнить build.bat и run.bat. JAR в этой ветке взят из main и до сборки не включает доработку.

## Что объяснить
Command инкапсулирует действие, CommandHistory хранит снимки до действия. Лимит меняет хранение истории и не меняет сами команды. В HistoryLimitTest установлен лимит 2: после трёх действий доступны только две последние отмены. Вручную 101 раз нажимать кнопки не нужно.

Перед отправкой прочитай diff, запусти проверку и внеси собственные необходимые правки. Не подписывайся другим аккаунтом ради смены автора.
